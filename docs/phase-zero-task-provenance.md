# Phase Zero — Task Provenance and Containment

Date opened: 2026-08-22  
Baseline: `20d7dd5369991fe45422b12755187ad6d3a8fc86` (`origin/main`)  
Initial branch: `codex/task-provenance-containment`

## Decision

The acquisition task backlog is not trusted operational truth. It is a mixed
compatibility projection containing legacy operator entries, event-derived
work, automated suggestions, and rows with no source attribution. Phase Zero
measures and contains that mixture before any quarantine or cleanup.

AI must remain proposal-first. It may draft a next action with cited CRM
evidence, but an authenticated person must review the fields and approve the
governed workflow before a canonical work item is created.

## Read-only production evidence

The aggregate census on 2026-08-22 selected no customer names, phone numbers,
addresses, messages, or record identifiers:

- 208 acquisition work items; 193 active and 15 completed.
- 68 automation-generated items, all still active: 21 `mojo_auto_evaluate`,
  18 `mojo_sync`, 10 `mojo_batch_evaluation`, 10 `batch-briefing-v2`, and 9
  `mojo`.
- 80 unattributed items, of which 75 remain active.
- 47 rows claim a legacy operator source (`lead_detail_task`, `calendar`, or
  `calendar_new_task`), of which 37 remain active. They are not called
  authenticated or verified because their metadata has no actor identity.
- 13 event-derived items, all active.
- All 208 lack authenticated `created_by` provenance; 195 lack a durable event
  identifier; 167 active items are more than 60 days old; 16 have no due date;
  3 are unlinked; and 13 are possible duplicates by contact, action, and due
  date.

## This release

1. Add a service-role-only aggregate RPC and authenticated no-store API for the
   provenance census.
2. Show the evidence on Tasks as operator-entered, event-backed, automation
   review, unattributed, and possible-duplicate counts.
3. Keep every existing task and all current operating lanes unchanged.
4. Correct the website booking audit row so it is a `status_change`, not a
   duplicate authoritative task. The actual appointment activity remains.

## Writer policy

- `governed_human`: created through the authenticated canonical work-item API.
- `approved_workflow`: created only after the durable workflow approval gate.
- `legacy_operator`: a historical source claims operator creation, but lacks
  authenticated actor provenance.
- `event_derived`: tied to a durable call, message, booking, appointment, or
  workflow-run identifier.
- `automation_unreviewed`: generated by Mojo, briefing, reminder, or other
  heuristic automation without a human decision.
- `unknown`: no trustworthy source evidence.

No class changes task status by itself. The classification is evidence for a
later reviewed quarantine decision, not an AI verdict about whether a task is
valuable.

## Approval boundary

The aggregate census, UI evidence, and correction of future duplicate booking
audit rows are reversible and do not mutate existing task records. Moving any
existing task out of Current Work, cancelling it, completing it, merging it, or
deleting it remains a separate production decision requiring explicit human
approval after signed-in verification of this report.

## Approved quarantine — 2026-08-22

After the census was deployed and verified in the signed-in production Tasks
workspace, Ernest explicitly approved quarantining the 68 active rows classified
`automation_unreviewed`.

The implementation changes only the rebuildable `work_items.operational_lane`
projection:

- Explicit automation provenance moves to `quarantine`.
- The 75 active unattributed rows remain visible and are not reclassified.
- Current Work and Review Debt exclude quarantine; All Records still includes
  every source row and therefore remains the reconciliation total.
- Quarantined work is visible in its own lane and retains the reviewed-change
  lock. No task is deleted, completed, cancelled, reassigned, redated, or
  rewritten by quarantine.
- If source provenance is later corrected, the projection recalculates the
  appropriate current or review lane without changing source task state.
